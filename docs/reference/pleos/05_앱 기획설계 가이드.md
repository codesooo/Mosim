# Pleos Connect — 앱 계획·설계 가이드 (Vehicle App Planning Guide)

> 출처: Pleos Playground 개발자 문서 (https://document.pleos.ai/docs/pleos-only/vehicle-app-planning-guide/intro)
> 수집일: 2026-11-07. 공모전 심사 기준 중 "차량 특화성"과 바로 연결되는 문서입니다.

모바일 앱을 Pleos Connect 앱으로 바꾸거나 처음부터 설계할 때 꼭 고려할 사항을 다룹니다. 구성: 주행 안전 설계 / 지역별 주행 규제 / 앱 카테고리 / 앱 구조·동작 모델 / 하드웨어 접근 정책 / SDK API 정책 / API 호환성·가용성 / 보안·개인정보 / 성능·리소스.

## 1. 주행 안전을 고려한 설계
<!-- 원문: /docs/pleos-only/vehicle-app-planning-guide/driver-distraction-guideline -->

앱은 운전자 주의를 분산시키지 않도록 설계해야 하며, 주행 중 사용 가능 여부와 기능 제한은 **주행 상태, 지역, 앱 카테고리**에 따라 달라집니다. AAOS 운전자 주의 분산 가이드라인을 준수합니다.

### 주행 규제 상태에 따른 앱 동작
앱은 **`CarUxRestrictions`**로 주행 중 제한 상태를 확인하고, 제한 대상 기능의 UI·동작을 축소하거나 비활성화해야 합니다. **주행 규제 상태에서 영상 재생을 시작·재개하지 않도록** 하고, 오디오 재생은 오디오 포커스 정책을 따릅니다. (구현: 06 개발 가이드의 주행 규제 개발 가이드)

### 주의 분산 방지 UX 원칙
- **시선 분산 최소화**: 운전 정보는 짧은 시간에 이해되게 간결히. HUD·클러스터·OSD 영역을 쓰면 해당 정책 준수. 주행 중 동영상·애니메이션·움직이는 이미지 최소화. 장식적·반복적으로 움직이는 요소 지양.
- **정보 구조·인터랙션**: 주행 중 필요한 정보·기능에 우선순위. 최소 조작으로 도달하도록 메뉴 단순화. 자주 쓰는 기능은 첫 화면·상단에, 드롭다운·다단 메뉴 남용 금지. 자동 애니메이션·반복 화면 전환 최소화. 중요한 오디오 안내 중에는 오디오 포커스 정책에 따라 미디어 일시정지/볼륨 조정.
- **터치 조작 최적화**: Pleos Connect UI Design Guide의 큰 터치 영역, 높은 대비, 텍스트 최소화 적용. 터치 최소화, 음성·물리 버튼 등 차량 입력과 연계. 게임·인터넷 서핑·피트니스 등 주의 분산 활동 유도 금지.
- **텍스트 입력 최소화**: 검색·로그인도 키보드보다 프리셋, 최근 항목, 음성 입력 우선. 음악 앱은 프리셋 플레이리스트·최근 재생·즐겨찾기를 첫 화면에.

## 2. 지역별 주행 규제 정책
<!-- 원문: /docs/pleos-only/vehicle-app-planning-guide/driving-restiction-policy -->

> 플랫폼 버전과 양산 차량에 따라 정책이 다를 수 있습니다.

주행 규제는 차량의 속도·기어·브레이크 등 하드웨어 신호와 지역별 안전 규정에 따라 적용됩니다. (판단 기준 상세: 01 문서 6절 — 북미는 P 또는 N+주차브레이크만, 그 외 지역은 5 km/h 이하에서 P / 주차브레이크 / Auto Hold 중 하나면 해제)

### Distraction Optimization(DO) 미선언 시 기본 동작
| 상황 | DO 미선언 시 앱 사용 |
| --- | --- |
| Parking(주차) | 사용 가능 |
| Drive(주행) | **사용 불가** |

→ 주행 중에도 쓰이는 앱이라면 DO 선언과 `CarUxRestrictions` 대응이 필요합니다.

### 주행 상황별 기능 제한 (✅ 가능, ⛔ 제한, 음성한정)
열 순서: 키보드 `NO_KEYBOARD(8)` / 다이얼패드 `NO_DIALPAD(1)` / 검색 `NO_KEYBOARD(8)+NO_FILTERING(2)` / 미디어 앱 로그인·설정·검색 `NO_SETUP(64)+NO_KEYBOARD(8)+NO_FILTERING(2)` / 디지털키·도어·시트·차량 설정 `NO_SETUP(64)` / 동영상 시청 `NO_VIDEO(16)` / 내비게이션 검색 `NO_KEYBOARD(8)+NO_FILTERING(2)` / QR 로그인 `NO_SETUP(64)` / 매뉴얼(대용량 텍스트) `LIMIT_CONTENT(32)+LIMIT_STRING_LENGTH(4)`

| 지역 | 상황 | 키보드 | 다이얼패드 | 검색 | 미디어 로그인·설정·검색 | 차량 설정 | 동영상 | 내비 검색 | QR 로그인 | 매뉴얼 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 북미 | Parking | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| 북미 | Driving | ⛔ | ⛔ | 음성한정 | ⛔ | ⛔ | ⛔ | ⛔ | ⛔ | ⛔ |
| 유럽 | Parking | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| 유럽 | Driving | ✅ | ✅ | ✅ | ⛔ | ⛔ | ⛔ | ✅ | ⛔ | ⛔ |
| 그 외(한국 포함) | Parking | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| 그 외(한국 포함) | Driving | ✅ | ✅ | ✅ | ✅ | ⛔ | ⛔ | ✅ | ⛔ | ⛔ |

- 「검색」은 웹 검색이 아니라 차량 인포테인먼트 내 통합 검색입니다.
- InfoLINK용 앱은 지역별 키보드 분기가 필요할 수 있음(문의: partnership@pleos.ai).
- 원문 표에서 "그외 지역"의 QR 로그인은 ⛔이지만, InfoLINK 보충 문서에는 한국(KOR)에서 대부분 QR 화면이 허용된다고 되어 있습니다(01 문서 6절). 한국 기준 앱이라면 두 문서를 함께 확인하세요.

## 3. 앱 카테고리
<!-- 원문: /docs/pleos-only/vehicle-app-planning-guide/app-category -->

설계 시점부터 카테고리를 명확히 정의해야 합니다(프로젝트 생성 시에도 필수 입력).

| 카테고리 | 핵심 목적 |
| --- | --- |
| Maps/Navigation | 위치 기반 길 안내 |
| Mobility Services | 이동 수단/이동 서비스 제공 |
| Lifestyle | 일상생활 관리 및 향상 |
| Entertainment | 오락 및 여가 제공 |
| Business | 업무 및 생산성 지원 |
| Music/Audio | 오디오 콘텐츠 중심 |
| Kids | 아동 대상 콘텐츠 |
| Social/Communication | 사람 간 소통 및 네트워크 |

카테고리와 주행 상태에 따라 주행 중 기능 범위가 달라집니다. **주행 중 기능이 제한적으로 허용될 수 있는 카테고리 예시**(실제 적용은 주행 상태·지역 정책에 따름):
- **Music/Audio**: 앨범 아트 등 단순 시각 정보, 재생/일시정지/곡 넘기기, 음악 스트리밍 청취, 라디오 채널 변경, 오디오북 재생
- **Maps/Navigation**: 경로 안내·실시간 교통, 간결한 지도, TBT 음성 안내, 경로 탐색, 빠른 길 안내, 주변 교통 상황
- **Mobility Services**: 주행과 밀접한 차량 관리 서비스, 현재 위치 기반 즉각 정보, **전기차 충전소 찾기 및 경유지 설정**, 가까운 주유소 탐색, 접근 가능한 주차장 위치 확인

## 4. 앱 구조 및 동작 모델
<!-- 원문: /docs/pleos-only/vehicle-app-planning-guide/app-structure-screen-model -->

Pleos Connect는 **Driving view + 앱 영역(최대 2개 앱)**의 차량용 멀티 윈도우 환경입니다.

### 화면 구성
- **Driving view**: 운전자 가까운 고정 영역, 앱이 가리거나 종료할 수 없음.
- **앱 영역**: 차량·디스플레이 구성에 따라 1~2개 window.
- `portrait`: 앱 영역 중 window 하나 사용(두 앱 동시 표시 시 보통 각각 portrait).
- `landscape`: 한 앱이 두 앱 영역을 확장해 사용.
- **portrait와 landscape 화면을 각각 설계**: portrait에는 핵심 기능·주요 정보, landscape에는 부가 정보·확장 기능.
### 앱 실행 및 window 전환
- 새 앱은 현재 표시 중인 앱의 방향 기준으로 표시(landscape 앱 하나면 새 앱도 landscape, portrait 두 개면 새 앱은 primary window에 portrait).
- 화면에서 사라져도 종료가 아니라 백그라운드에 남을 수 있고, 표시 중 앱이 종료되면 최근 사용 순으로 다시 표시될 수 있음 → foreground 재진입 상황 고려.
- 사용자가 window bar나 제스처로 위치·크기를 바꿀 수 있으므로 유연한 화면 구성 필요.
### 화면 방향 및 크기
- `screenOrientation` 미지정 시 portrait(window 1개), `landscape` 지정 시 window 2개 영역 사용.
- 방향·window 크기 변경에도 레이아웃이 깨지지 않게 반응형 레이아웃 사용. `AndroidManifest.xml`의 `screenOrientation` 기준으로 동작.
### 포그라운드·백그라운드 전환
화면 분할, 위치 변경, 다른 앱 실행, 주행 상황 변화로 전환이 잦습니다.
- 포그라운드 진입 시 상태 복원, 크기·방향에 맞게 UI 재구성
- 백그라운드 전환 시 화면 갱신·애니메이션·불필요한 센서 수집 중단
- 오디오 재생·통신·다운로드 등 지속 작업은 실행 조건과 중단·재개 정책 정의
- 백그라운드 상주·타이머·폴링·네트워크 요청 최소화
- 프로세스 재생성 시에도 사용자 데이터·진행 상태 복원 전략

## 5. 하드웨어 접근 정책
<!-- 원문: /docs/pleos-only/vehicle-app-planning-guide/platform-api-architecture -->

- **직접 접근 금지**: 차량 물리 제어나 센서에 직접 접근 불가.
- **플랫폼 API 우선**: 차량 상태는 Pleos Connect SDK의 표준 플랫폼 API로 확인·제어.
- **모바일 전용 API 주의**: Telephony(전화), SMS, 일부 센서(자이로, 근접 등), 캘린더, 주소록 등은 제공되지 않거나 제한될 수 있음 → 필수가 아니면 제거하거나, 지원 여부를 확인한 뒤 동작하는 Optional 구조로 설계.
### 주행 중 네트워크 대응
셀룰러/Wi-Fi 단절이나 대역폭 급감에 대비해 오프라인·저대역폭에서도 핵심 기능이 동작하도록:
- 캐싱(최근 콘텐츠 로컬 저장), 재시도 로직과 적절한 타임아웃, 오프라인 모드 안내 UI.

## 6. SDK API 정책
<!-- 원문: /docs/pleos-only/vehicle-app-planning-guide/pleos-connect-sdk-api -->

- **표준 우선**: 같은/유사 기능의 API가 AAOS 표준에 있으면 그것을 권장하며, Pleos SDK는 중복 기능을 제공하지 않음.
- **확장 기능**: AAOS 표준으로 접근 불가하거나 제조사 고유 보안·특화 제어가 필요한 영역만 Pleos SDK 전용 API 제공.
- **하위 호환**: SDK API가 AAOS 표준으로 수용돼도 최소 2개 메이저 버전까지 유지.
### API 선택 기준 ⭐
| 구분 | 접근 경로 | 대상 기능 예시 |
| --- | --- | --- |
| 표준 데이터 | **AAOS Car API** | **속도, 기어 상태, 외기 온도, 연료 레벨 등** |
| 특화 기능 | Pleos Connect SDK | 제조사 전용 시트 제어, 특화 라이팅, 고유 보안 인증 등 |

→ 차속·기어는 Pleos Vehicle SDK가 아니라 **AAOS `CarPropertyManager`/`VehiclePropertyIds`**로 읽는 구조입니다.

## 7. API 호환성 및 가용성
<!-- 원문: /docs/pleos-only/vehicle-app-planning-guide/api-compatibility-availability -->

| Pleos Connect SDK | 차량 모델별 API 호환성 |
| --- | --- |
| Vehicle SDK | 모델에 따라 다름 → 도메인별 `checkXXXCapabilities`로 확인 |
| NaviHelper SDK | 내비게이션 탑재 차량에 한해 전체 호환 |
| TextToSpeech, SpeechToText | 전체 호환 |
| FusedLocation SDK | 모델에 따라 다름 → `isSupported()`로 확인 |

**AAOS Vehicle Property**: 지원 여부·접근 상태는 모델·프로퍼티마다 다를 수 있습니다. 정의·ID는 Google의 `VehiclePropertyIds`, 실제 지원·접근 가능 여부는 `CarPropertyManager`로 확인합니다.
- 모델명으로 분기하지 말고 `VehiclePropertyIds`·`CarPropertyManager`로 실제 지원 여부를 확인하세요.
- Pleos SDK가 제공하지 않는 특수 프로퍼티가 필요하면 직접 구현 전에 기술 지원팀 검토를 요청하세요.

## 8. 보안 및 개인정보 보호
<!-- 원문: /docs/pleos-only/vehicle-app-planning-guide/security-privacy -->

차량은 여러 사람이 함께 쓰는 기기입니다. (App Market 등록 시 상세 기준은 앱 보안 가이드)
- **계정/세션**: 소유자 변경·운전자 교체 시 쉽게 로그아웃·계정 전환. 소셜 로그인·OTT 토큰은 Keystore 등 안전한 저장소에.
- **개인정보 최소 수집**: 위치·음성·계정 정보 요구 시 "왜 필요한지" 명확히, 동의 플로우는 간단하게. 불필요한 PII 저장 금지, 로그의 개인정보는 마스킹.
- **차량 외부로 나가는 데이터**: Telemetry/분석 이벤트에서 차량 ID·사용자 ID 익명화/가명화 정책 수립. 운전 중 행동 데이터를 마케팅 목적으로 쓰지 않도록 구분.

## 9. 성능 및 리소스 효율
<!-- 원문: /docs/pleos-only/vehicle-app-planning-guide/performance-resource-mgmt -->

여러 앱이 동시에 동작하므로 빠른 기동과 가벼운 상주가 중요합니다.
- **시작 시간**: Cold start 시 스플래시에 오래 머물지 않게 최소 초기화, 나머지는 lazy loading.
- **CPU 기준**: 내비게이션 앱(주행 중) **15% 이하** / 내비 외 앱(주행 중) **5% 미만** / 모든 앱(정차 중) **25% 이하**
- **RAM 400 MB 이하**
- 백그라운드 긴 작업·타이머·폴링 최소화, RecyclerView·캐시 전략으로 메모리 최적화.
- **오디오·미디어**: Pleos Connect 오디오 포커스 정책 준수, 포커스 획득·상실 대응 로직 필수 구현(06 개발 가이드 참고).
