## 1. Pleos Connect SDK Overview
<!-- 원문: /docs/pleos-only/connect-sdk-pleos/ -->

Pleos Connect SDK는 Pleos Connect 환경에서 동작하는 인포테인먼트 앱 개발용 통합 개발 도구입니다. Android Automotive OS(AAOS) 기반으로 표준화된 인터페이스를 제공해, 복잡한 하드웨어 연동 없이 차량 관련 앱을 개발할 수 있습니다.

### Modules
- **Vehicle SDK**: 차량 상태 조회와 차량 제어 API
- **NaviHelper SDK**: 경로 안내 제어와 내비게이션 정보 조회 API
- **TextToSpeech SDK**: 음성 합성 API
- **SpeechToText SDK**: 음성 인식 API
- **FusedLocation SDK**: 차량 위치 정보 API
### API policy
동일·유사 기능의 API가 Android Automotive OS에 있으면 플랫폼 파편화를 줄이기 위해 **Android Automotive에 맞추는 것이 원칙**입니다. Vehicle SDK 기능이 이후 Android Automotive에 수용되면 최소 2개 major version 동안 하위 호환을 보장하고, 그 이후는 별도 정책·릴리스 노트로 안내합니다.

**Vehicle SDK API 사용 및 앱 심사**: API 지원 여부는 도메인별 `checkXXXCapabilities`로 확인합니다. 필요한 퍼미션을 앱에 선언해야 하며, 퍼미션은 **Pleos App Market과 사전 협의·승인된 범위 안에서만** 쓸 수 있습니다. 승인되지 않은 퍼미션을 선언하거나 해당 API를 호출하면 앱 심사를 통과할 수 없습니다.

## 2. Pleos Connect 앱 개발 시작하기 (Quick start)
<!-- 원문: /docs/pleos-only/getting-started -->

Android Studio에서 프로젝트를 만들고 Pleos Connect Emulator를 실행한 다음, Vehicle SDK의 첫 API를 호출하는 빠른 시작 가이드입니다.

### 사전 준비
- Android Studio
- Android SDK API 34
- Android 프로젝트의 `minSdk` **API 28 이상**
- Pleos Connect Emulator system image
### 1) Android 프로젝트 만들기
File > New > New Project → Templates에서 **Car 또는 Automotive** 카테고리 → Empty Activity → 언어 Kotlin, Minimum SDK API 28 이상 → Finish. 생성 후 `app` 모듈이 정상 빌드되는지 먼저 확인합니다.

### 2) Pleos Connect Emulator 설치 및 구성
1. Tools > SDK Manager > SDK Update Sites → Add
2. Name: `Pleos Connect System Image`, URL: 제공받은 Pleos Connect Emulator 다운로드 URL
3. SDK Platforms에서 API 34의 Pleos Connect system image 설치 후 Android Studio 재시작
4. Tools > Device Manager > Create device → Automotive → Pleos Connect 디바이스 생성
5. AVD 고급 설정: **Boot option = Cold boot, RAM = 4 GB**, API 34 Pleos Connect system image 선택
6. Device Manager에서 AVD 실행
### 3) Vehicle SDK 가져오기
`settings.gradle.kts`:
```kotlin
dependencyResolutionManagement {
    repositoriesMode.set(RepositoriesMode.FAIL_ON_PROJECT_REPOS)
    repositories {
        google()
        mavenCentral()
        maven {
            url = uri("https://nexus-playground.pleos.ai/repository/maven-releases/")
        }
    }
}
```
`app/build.gradle.kts`:
```kotlin
dependencies {
    implementation("ai.pleos.playground:Vehicle:2.3.1")
}
```
(이 페이지 예시는 2.3.1이며, 최신 릴리즈는 **2.3.2**입니다. 아래 릴리즈 노트 참고.) Sync Now 후 의존성을 찾지 못하면 Maven 저장소 접근 권한과 SDK 버전을 확인하세요.

### 4) 차량 권한 선언 (`app/src/main/AndroidManifest.xml`)
```xml
<manifest xmlns:android="http://schemas.android.com/apk/res/android">
    <uses-permission android:name="pleos.car.permission.CAR_DOORS" />
    <application ...>
        ...
    </application>
</manifest>
```

### 5) 첫 번째 API 호출
```kotlin
val vehicle = Vehicle(context)
vehicle.initialize()
 
val door = vehicle.getDoor()
door.getCurrentDoorPosition(
    area = DoorArea(DoorValue.ROW_1_LEFT),
    onComplete = { pos: Int? ->
        // Use the current door position.
    },
    onFailed = { e: Exception ->
        // Handle the Vehicle SDK error.
    }
)
 
// Do not call release() here.
// Call release() when the app no longer needs Vehicle SDK (for example, in onDestroy()).
```
`onComplete`/`onFailed`는 비동기 콜백이며, `vehicle.release()`는 콜백 처리 완료 후 또는 SDK를 더 쓰지 않는 생명주기 시점(예: `onDestroy`)에 호출하세요.

### 6) 에뮬레이터에서 확인
에뮬레이터 완전 부팅 확인 → 실행 대상 기기로 Pleos Connect Emulator 선택 → Run.
값을 읽지 못하면: `minSdk` 28 이상인지 / `pleos.car.permission.CAR_DOORS` 선언 여부 / SDK 의존성 동기화 / 에뮬레이터 정상 실행 / `onFailed` 예외 메시지 확인.

### 다음 단계 (권장 순서)
앱 계획·설계 가이드(화면, 주행 중 사용성, 성능, 개인정보) → 앱 개발 가이드 → SDK·API 문서 → Vehicle SDK 권한·Capability·Get → Sample App 가이드 → Virtual Console로 차량 상태 연동 테스트 → 앱 등록·배포 가이드.

## 3. 프로젝트 생성 및 SDK 사용 신청
<!-- 원문: /docs/pleos-only/create-my-project -->

### 회원 가입
Pleos Playground 접속 → 우측 상단 로그인 → 로그인 화면 하단 **Pleos 계정 만들기** → 약관 동의·정보 입력 → 로그인.

### 프로젝트 생성
상단 GNB **Workspace > My Project** → 프로젝트 생성 → 입력:
- 프로젝트 이름(나중에 변경 가능), 개발사명, **카테고리**(개발 과정에서 필수 정보이므로 미리 정의 권장), 애플리케이션 설명 → 생성
### 프로젝트 정보 확인
- 키 정보 > **프로젝트 ID(Key)**: 앱 심사 요청 시 Pleos App Market Console에 입력
- SDK > **클라이언트 ID / 클라이언트 시크릿**: 서버 연결이 필요한 SDK(TextToSpeech, SpeechToText) 사용 시 필요
- 테스트 정보 > CRN: Emulator 2.1.0 이후로는 CRN 입력 불필요
### SDK 사용 신청
프로젝트 정보 화면 좌측 사이드바 SDK → 사용할 SDK 선택 → 상태 확인:
- **준비 중**: 신청 버튼 없음, `Comming Soon` 배지. FusedLocation, TextToSpeech, SpeechToText, Vehicle Control SDK가 해당(원문 기준).
- **사용 가능**: 신청 없이 사용 가능하거나 승인 완료. **Vehicle State와 NaviHelper SDK는 신청 없이 바로 사용 가능.**
- **신청 필요**: 신청 클릭 → 정보 입력·제출 → 검토 중 → 승인 시 사용 가능 / 반려 시 반려됨.
- **제휴 계약 필요**: 웹 신청 불가, 서비스 계약 담당자에게 별도 문의.
> 설명회 참고: 공모전 개발 단계에서는 별도 승인 없이 매니페스트에 권한을 선언해 에뮬레이터에서 테스트할 수 있다고 안내됐습니다. 위 "준비 중" 상태와 실제 에뮬레이터 동작이 다를 수 있으니 직접 확인하세요.

## 5. 폼 팩터 테스트 가이드
<!-- 원문: /docs/pleos-only/app-test-guide/form-factor-test-guide -->

실행 중인 Emulator에 가상 디스플레이를 만들고, **FormFactorConsole** 앱에서 디스플레이 종류·방향을 바꿔가며 앱 화면이 정상 표시되는지 확인합니다.

**준비**: Android Studio와 Platform-Tools, **Go 1.22 이상**, 테스트할 앱이 설치된 Emulator, `8095`·`8096` 포트 사용 가능 환경.
⚠️ 가상 디스플레이는 Emulator를 **별도 창으로 실행할 때만** 표시됩니다. Running Devices 도구 창 내장이나 Headless 모드로 실행하지 마세요.

1. **AVD 실행 후 확인**: `adb devices` (여러 기기면 `<SERIAL>`에 예: `emulator-5554`), `adb emu avd name`으로 AVD 이름 확인(예: `Pleos_Connect_v2.0`).
2. **Host Display Bridge 실행**: host-display-bridge.zip 다운로드·압축 해제 → 해당 디렉터리에서 `go run . --avd "<AVD_NAME>"`. `listening on http://127.0.0.1:8096` 로그가 보이면 정상이며 테스트가 끝날 때까지 터미널 유지. AVD를 못 찾으면 완전 부팅 여부와 이름 확인, 여러 AVD 실행 중이면 나머지 종료 권장.
3. **FormFactorConsole 접속**: 에뮬레이터에서 앱 실행. 상단에 `UNAVAILABLE`이면 Bridge 실행 확인 후 Refresh. `DISCONNECTED`와 "DISPLAY2가 없습니다"가 보이면 준비 완료.
4. **테스트**: Display preset에서 폼 팩터 선택 → Orientation(Portrait/Landscape) → dp·DPI·px 확인 → 가상 디스플레이 생성(예: 12.9인치 Portrait, 14.6인치 Landscape) → `DISPLAY2` 창에서 앱 목록(안 열리면 "앱 목록 실행") → 확인 항목: 화면 요소 잘림·겹침 / 텍스트·이미지·아이콘 크기·정렬 / 가로·세로 레이아웃 / 터치·화면 전환. 다른 폼 팩터는 가상 디스플레이 제거 후 반복.
   ⚠️ 가상 디스플레이를 제거하면 그 디스플레이의 앱이 강제 종료됩니다.
5. **종료**: 가상 디스플레이 제거 → Bridge 터미널 `Ctrl+C` → `adb forward --remove tcp:8095`

## 6. 지역별 주행 규제 정책 (InfoLINK 추가 구현 항목)
<!-- 원문: /docs/pleos-only/infolink-emulator/driving-restiction-policy -->

InfoLINK에서 동작하는 앱도 Pleos Connect 지역별 주행 규제 정책을 따라야 하며, 이를 위한 추가 구현 항목을 보충하는 문서입니다.

- 주행 상황(Parking, Idling, Driving)과 지역에 따라 기능별 사용 가능 여부가 다릅니다(✅ 사용 가능, ⛔ 제한, `음성한정`).
- 앱은 `product.sw.target_region`으로 지역을 구분: 한국 `KOR`, 유럽 `EUR`, 북미 `USA`, `CAN`.
- QR 코드 노출 화면은 `CarUxRestrictions.UX_RESTRICTIONS_NO_SETUP_QR_SCAN`에 해당(사유: 휴대전화 활용 유도). **한국은 대부분 화면에서 주행 중 QR 사용 가능**, 북미·유럽·기타 지역은 ⛔. (Wi-Fi 연결 > URL QR 코드만 한국에서 규격 미정)
  | 모드 | 화면/시나리오 | 주행 중 잠금 처리 | 북미 | 유럽 | 한국 | 기타 |
  | --- | --- | --- | --- | --- | --- | --- |
  | 연결(블루투스) | BYOD > QR 코드 | QR 이미지를 다른 이미지로 대체 | ⛔ | ⛔ | ✅ | ⛔ |
  | 연결(Wi-Fi) | Wi-Fi 연결 > URL QR 코드 | 콘텐츠 영역 차단 | ⛔ | ⛔ | 규격 미정 | ⛔ |
  | S/W 업데이트 | What's New > QR 코드 | 콘텐츠 영역 차단 | ⛔ | ⛔ | ✅ | ⛔ |
  | 매뉴얼 | QR 코드 | 콘텐츠 영역 차단 | ⛔ | ⛔ | ✅ | ⛔ |
  | 고객센터 | 설정/활성화 > 인증 코드 > QR 코드 | QR 이미지를 다른 이미지로 대체 | ⛔ | ⛔ | ✅ | ⛔ |
  | 차량 관리 | 서비스 점검 > QR 코드 | 콘텐츠 영역 차단 | ⛔ | ⛔ | ✅ | ⛔ |
  | 프로필 | QR 코드 | QR 이미지를 다른 이미지로 대체 | ⛔ | ⛔ | ✅ | ⛔ |

### 주행 규제 판단 기준
차량 하드웨어 신호(속도, 기어, 브레이크 등)로 판단하며, 지역 법규에 따라 해제 조건이 다릅니다.
- **북미**: Auto Hold를 정차로 인정하지 않음. 시동(IGN1)/엔진이 꺼져 있으면 해제. 속도 5 km/h 이하에서 자동 변속기는 기어 P, 수동 변속기는 Parking Brake ON + 기어 N일 때 해제.
- **북미 외 지역(한국 포함)**: 시동/엔진 꺼짐이면 해제. 속도 5 km/h 이하에서 다음 중 하나라도 충족하면 해제: 기어 P / Parking Brake ON / Auto Hold 활성(장착 차종). 모두 불충족이거나 5 km/h 초과 시 규제 ON.
